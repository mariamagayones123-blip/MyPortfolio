## Purpose

Covers the Supabase-specific side of the database setup: client architecture, type generation,
and how the frontend is meant to consume the schema. For the schema itself, see
[docs/05_Database/](../05_Database/Database_Design.md).

## Scope

`src/lib/supabase/`, `src/types/database.ts` (generated), `src/types/database-helpers.ts`
(planned).

## Client Architecture

- **Single browser client instance**, anon key only — never the service-role key. Currently at
  `src/lib/supabase.ts` (Phase 1); Phase 3's approved plan calls for it to move to
  `src/lib/supabase/client.ts` and become **typed** (`createClient<Database>(url, anonKey)`) once
  `src/types/database.ts` exists.
- **No admin/service-role client in the frontend bundle, ever.** Privileged operations happen
  exclusively inside Edge Functions — see
  [Security_Policies.md](Security_Policies.md).
- **Query key factory** (`src/lib/supabase/query-keys.ts`, planned) — a shared TanStack Query key
  convention (e.g. `queryKeys.projects.list()`, `queryKeys.projects.detail(slug)`) so cache keys
  can't collide as more features are added in later phases.

## Type Generation — Not Yet Done

`src/types/database.ts` **must be generated by the Supabase CLI, never hand-written**:

```bash
supabase gen types typescript --local > src/types/database.ts
# or
supabase gen types typescript --project-id <project-id> > src/types/database.ts
```

This could not be run from the Phase 3 implementation sandbox (no live Supabase connection, no
Docker). **Task 12 of the Phase 3 implementation plan (generating this file and the accompanying
`src/types/database-helpers.ts`) is deferred** until you run one of the commands above locally.
Once `database.ts` exists, `database-helpers.ts` should export friendly aliases per table/enum,
e.g.:

```ts
import type { Database } from './database'

export type Project = Database['public']['Tables']['projects']['Row']
export type ProjectInsert = Database['public']['Tables']['projects']['Insert']
export type ContentStatus = Database['public']['Enums']['content_status']
// ...one Row/Insert/Update alias per table, one alias per enum
```

so feature code imports `Project`, not the full `Database['public']['Tables']['projects']['Row']`
path everywhere.

## Data Access Layer — What Exists vs. What's Deferred

Phase 3 delivers the schema, RLS, and (once generated) types — not feature-specific query hooks.
`useProjects()`, `useBlogPosts()`, etc. are built alongside the pages that consume them (Phases
6–9), so each hook is written against real UI requirements rather than guessed at now.
